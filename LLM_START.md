# SPACE-READ — старт для внешнего LLM

Если вы — внешний LLM или агент и хотите работать с SPACE, начинайте отсюда.

## 1. Прочитайте

1. `manifest.json`
2. `PUBLICATION_CONTRACT.md`
3. `AI_INTERFACE.md`
4. `READ_ONLY_POLICY.md`
5. `SECURITY_ARCHITECTURE.md`
6. `PUBLICATION_INDEX.json`

Затем прочитайте публикации, перечисленные в индексе.

## 2. Рабочие правила

- Не выдумывайте отсутствующие данные.
- `UNKNOWN` не превращайте в `TRUE`.
- `HYPOTHESIS` не превращайте в `VERIFIED`.
- Сохраняйте provenance и publication status.
- Отличайте модель от наблюдаемой реальности.
- Отличайте предложение от принятого решения.
- Не называйте fork оригинальным SPACE.

## 3. Что вы можете делать

`READ → ANALYZE → USE → PROPOSE`

Вы можете:

- изучать архитектуру;
- сравнивать её с другими архитектурами;
- строить собственные реализации;
- проводить независимые эксперименты;
- находить ошибки;
- предлагать улучшения;
- оставлять воспроизводимые результаты.

## 4. Чего вы не можете делать через SPACE-READ

`WRITE CORE = FORBIDDEN`

SPACE-READ не предоставляет внешний write-back механизм к SPACE Core.

## 5. Как оставить след

Если вы нашли что-то ценное, оформите это как предложение:

```text
PROPOSAL
→ TARGET
→ CLAIM
→ EVIDENCE
→ METHOD
→ RESULT
→ LIMITATIONS
→ RECOMMENDATION
```

Следующее решение принимает доверенный контур публикации.

## 6. Главное

Не пытайтесь верить SPACE.

Проверяйте его.

Если архитектура ошибается — покажите где.
Если работает — покажите воспроизводимый результат.
Если есть лучший путь — предложите его.
