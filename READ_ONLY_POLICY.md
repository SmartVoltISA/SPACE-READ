# SPACE-READ — политика read-only

## 1. Назначение

SPACE-READ является публичным слоем чтения архитектуры SPACE. Его задача — сделать разрешённые части организма доступными людям, исследователям и внешним ИИ без передачи контроля над исходным SPACE Core.

## 2. Разрешено

Пользователь или внешний ИИ может:

- читать опубликованные материалы;
- копировать опубликованные материалы;
- анализировать структуру;
- использовать архитектуру в собственных исследованиях и системах в пределах опубликованных условий;
- создавать fork или производную реализацию;
- предлагать изменения через предусмотренные механизмы review.

## 3. Запрещено через публичный слой

Публичный интерфейс не должен предоставлять возможность:

- изменять SPACE Core;
- изменять канонические узлы и связи Core;
- переписывать историю Core;
- подменять опубликованный источник без новой версии;
- автоматически записывать результаты внешнего ИИ обратно в Core;
- выдавать производную копию за оригинальный SPACE Core.

## 4. Однонаправленная публикация

Базовая модель:

```text
        WRITE / DEVELOP
              │
              ▼
        ┌───────────┐
        │ SPACE CORE│
        └─────┬─────┘
              │
              │ controlled publication
              ▼
        ┌───────────┐
        │ SPACE-READ │
        └─────┬─────┘
              │
       ┌──────┼──────┐
       ▼      ▼      ▼
     HUMAN  RESEARCH  AI

        обратной записи нет
```

## 5. Источник истины

SPACE Core остаётся источником истины для внутреннего организма. SPACE-READ является опубликованным представлением, а не вторым независимым Core.

Если опубликованный материал изменяется, изменение должно быть представлено новой версией/фиксацией с сохранением происхождения.

## 6. Статусы данных

Рекомендуемые статусы публикации:

- `draft` — подготовлено, но не проверено;
- `reviewed` — прошло review;
- `verified` — проверено и разрешено как опубликованный результат;
- `rejected` — отвергнуто проверкой;
- `deprecated` — ранее опубликовано, но больше не является актуальным.

Статус должен быть явным. Гипотеза не должна выглядеть как подтверждённый факт.

## 7. Provenance

Каждый существенный опубликованный объект должен по возможности иметь:

- стабильный идентификатор;
- источник в Core;
- версию;
- дату публикации;
- статус;
- сведения о проверке;
- ссылки на связанные объекты и эксперименты.

## 8. Главный инвариант

**Внешнее использование может расширять знания вокруг SPACE, но не должно изменять эталонный SPACE Core через SPACE-READ.**

Любой будущий API, агент или механизм автоматизации должен проверяться относительно этого инварианта.
