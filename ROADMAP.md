# SPACE-READ — дорожная карта

## Цель

Построить публичный, контролируемый и масштабируемый слой доступа к архитектуре SPACE, через который человек или внешний ИИ сможет **читать и использовать** опубликованную архитектуру, не получая возможности изменять эталонный SPACE Core.

- [x] Зафиксировать назначение репозитория.
- [x] Зафиксировать однонаправленную границу `SPACE Core → SPACE-READ`.
- [x] Зафиксировать различие между публичным чтением и правом записи.
- [x] Создать первоначальный статус проекта.

## Фаза 1 — Контракт публикации

- [ ] Определить, какие классы данных разрешено публиковать.
- [ ] Разделить данные на: аксиомы, определения, структуру, гипотезы, эксперименты, подтверждённое, отвергнутое и открытые вопросы.
- [ ] Определить обязательные метаданные каждой публикации: источник, версия, дата, статус, проверка, связь с Core.
- [ ] Зафиксировать правило: новая версия добавляется поверх старой; история не переписывается задним числом.
- [ ] Определить механизм маркировки `draft / reviewed / verified / rejected / deprecated`.

## Критерий готовности

SPACE-READ считается базово готовым, когда внешний человек или ИИ может:

1. однозначно определить, что он читает;
2. получить структуру и определения;
3. понять происхождение и версию данных;
4. использовать опубликованную архитектуру;
5. воспроизвести опубликованные результаты, где это предусмотрено;
6. не иметь технического пути обратной записи в SPACE Core через публичный слой.

## Главное правило развития

**Сначала опора → связь → проверка → следующий слой.**

Не усложнять интерфейс до тех пор, пока не определены базовые структуры и их инварианты.
