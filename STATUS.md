# SPACE-READ — текущий статус

**Статус:** FOUNDATION / READY FOR CONTRACT DESIGN

**Репозиторий:** `SmartVoltISA/SPACE-READ`

**Назначение:** публичный read-only слой архитектуры SPACE.

## Выполнено

### 1. Публичный репозиторий

- Репозиторий создан как Public.
- Название: `SPACE-READ`.
- Владелец: `SmartVoltISA`.
- Основная ветка: `main`.

### 2. Граница архитектуры

Зафиксирована модель:

`SPACE Core → SPACE-READ → человек / исследователь / внешний ИИ`

Публичный слой предназначен для чтения и использования опубликованной архитектуры. Обратная запись во внутренний SPACE Core не является частью модели.

### 3. Разделение доверия

Зафиксировано принципиальное различие:

- **Core** — источник истины и рабочий организм.
- **READ** — контролируемая публичная публикация.
- **Fork** — самостоятельная производная копия, не являющаяся оригинальным Core.

### 4. Документационная опора

Созданы:

- `README.md` — назначение и граница проекта;
- `ROADMAP.md` — последовательность развития;
- `STATUS.md` — журнал состояния;
- `READ_ONLY_POLICY.md` — правила read-only границы;
- `manifest.json` — будущая машинно-читаемая точка входа.

### 5. Принцип истории

Зафиксировано правило: новые состояния и версии публикуются как новые фиксации. История не должна переписываться задним числом.

## Что пока НЕ считается выполненным

Не считаются завершёнными следующие работы:

- перенос содержимого SPACE Core;
- формальный контракт схемы данных;
- read API;
- автоматическая синхронизация Core → READ;
- CI-проверки графов и идентификаторов;
- проверка write-back из внешнего ИИ;
- первая версионированная публикация архитектуры.

Это намеренно. Сначала фиксируется граница, затем контракт, затем данные, затем интерфейс и только после этого автоматизация.

## Ближайшая контрольная точка

**PHASE 1: Publication Contract**

Результатом следующего этапа должен стать формальный контракт: что именно можно публиковать, в каком формате, с каким статусом, источником, версией и происхождением.

## Критерий качества

Никакой опубликованный элемент не должен попадать в SPACE-READ только потому, что он существует в Core. Он должен иметь понятный статус публикации и происхождение.
